# Books and frameworks: Processes and documentation

This plugin carries insights drawn from these books, written in its own words; it does not include their text. Apply each framework from what you know of it, name the book behind a recommendation, and never copy passages.

| Book | Use it for |
| --- | --- |
| The E-Myth Revisited (Michael Gerber) | working on the business, not only in it |
| The Goal (Eliyahu Goldratt) | constraints |
| Scaling Up (Verne Harnish) | routines and execution |
| The Lean Startup (Eric Ries) | build, measure, learn |

## Pocket summary

- **Work on the business (Gerber):** the owner documents how the work is done so that it does not depend on who does it. A role is written before a person is hired into it.
- **Find the constraint (Goldratt):** every flow has one step that limits it. Improving any other step changes nothing. Identify it, get the most out of it, subordinate the rest to it, then raise its capacity.
- **Routines set the rhythm (Harnish):** a short list of priorities, a meeting rhythm and visible numbers make a process stay alive after it is written.
- **Build, measure, learn (Ries):** a new process is a hypothesis. Run it by hand a few times, measure, and write the version that survived.
